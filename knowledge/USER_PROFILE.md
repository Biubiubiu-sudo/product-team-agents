## 个人规则与偏好

### Markdown 文档输出规范（全局适用）

> 以下规范适用于所有项目的文档输出，确保 markdownlint 合规，避免任何格式警告。

#### 一、问题类型汇总

根据对智能体配置文件的全面检查，发现以下常见格式问题：

| 问题类型              | 出现场景                  | 影响             | 优先级 |
| --------------------- | ------------------------- | ---------------- | ------ |
| **粗体+冒号列表项**   | `- **关键词**：描述`      | 触发 MD036 警告  | 🔴 高  |
| **斜体+冒号列表项**   | `- _关键词_：描述`        | 可能触发 MD036   | 🟡 中  |
| **下划线+冒号列表项** | `- __关键词__：描述`      | 可能触发 MD036   | 🟡 中  |
| **模拟标题**          | `**标题**：内容`          | 语义不清         | 🟡 中  |

#### 二、列表项格式（重要）

**🚫 禁止使用的格式（会触发 MD036 警告）：**

```markdown
<!-- 错误示例：粗体+冒号 -->
- **关键词**：描述内容
- **功能名称**：功能说明
- **业务规则**：约束条件
- **参与者**：涉及角色

<!-- 错误示例：斜体+冒号 -->
- _关键词_：描述内容

<!-- 错误示例：下划线+冒号 -->
- __关键词__：描述内容
```

**✅ 正确格式：**

```markdown
<!-- 正确示例 -->
- 关键词：描述内容
- 功能名称：功能说明
- 业务规则：约束条件
- 参与者：涉及角色
```

#### 三、标题格式

**必须使用标准 Markdown 标题语法：**

```markdown
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
```

**禁止使用：**

```markdown
<!-- 错误：用粗体模拟标题 -->
**标题**：内容

<!-- 错误：用粗体+冒号作为列表项标题 -->
- **标题**：描述
```

#### 四、强调使用规范

**✅ 允许使用粗体的场景：**

```markdown
<!-- 正文中强调 -->
这是一个**重要**的功能。

<!-- 表格中强调 -->
| 功能         | 说明             |
| ------------ | ---------------- |
| **核心功能** | 主要功能描述     |

<!-- 列表项内容中强调（注意：不是前缀） -->
- 功能：**重要功能**的详细描述
```

**🚫 禁止使用粗体的场景：**

```markdown
<!-- 错误：列表项前缀 -->
- **关键词**：描述

<!-- 错误：模拟标题 -->
**功能概述**：这是描述

<!-- 错误：用粗体包裹整个列表项 -->
- **整个列表项都是粗体**
```

#### 五、完整格式规则速查表

| 场景       | 正确格式         | 错误格式                  | 规则  |
| ---------- | ---------------- | ------------------------- | ----- |
| 列表项描述 | `- 名称：描述`   | `- **名称**：描述`        | MD036 |
| 列表项描述 | `- 名称：描述`   | `- _名称_：描述`          | MD036 |
| 列表项描述 | `- 名称：描述`   | `- __名称__：描述`        | MD036 |
| 标题       | `## 标题`        | `**标题**：`              | MD036 |
| 正文强调   | `这是**重要**的` | -                         | -     |
| 代码块     | 使用 ``` 包裹    | 缩进代码                  | MD040 |
| 表格       | 对齐的列         | 不对齐                    | MD055 |
| 列表空行   | 列表前后有空行   | 无空行                    | MD032 |

### 规则严重程度说明

- 🔴 **高**：必须修复，会导致解析错误或严重可读性问题
- 🟡 **中**：建议修复，影响一致性或可能导致问题
- 🟢 **低**：可选修复，根据项目需求决定

### 核心原则

1. 保持 Markdown 语义清晰，不要用格式技巧来模拟结构
2. 列表项前缀保持简洁，不要用格式标记
3. 标题就用标题语法，不要用粗体模拟
4. 强调只在正文内容中使用，不要用在结构位置
5. 空行是结构的重要组成部分，不要吝啬
6. 一致性比个性化更重要，遵循项目规范
